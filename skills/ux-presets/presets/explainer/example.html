How a coding agent routes a request

A harness does not send every prompt to its best model. It reads the request first, then picks the cheapest model that can finish the job.

The short version

What happens between pressing Enter and seeing the first edit?

The router classifies the request, a model plans the work, and tools do it. The model never touches your files directly: every read and every edit is a tool call that the harness can allow, deny, or record.

The rule of thumbEasy and well-specified work goes to the fast model. Work that needs judgement goes to the strong one.

What each part does

Who is responsible for what?

  • Router

    Reads the request and the repository's shape, then names a model and a level of effort.

  • Fast model

    Renames, small fixes, tests for code that exists. Finishes in seconds.

  • Strong model

    Designs, migrations, anything where a wrong first step is expensive.

  • Tools

    The only way anything changes: read, edit, shell, browser. Each call is logged.

  3. 00:19Two edits and one test run, each a tool call.
  4. 00:41The tests pass and the answer is written.
